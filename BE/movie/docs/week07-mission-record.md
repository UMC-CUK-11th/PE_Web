# 7주차 미션 기록 초안

작성 기준: 자동 구현·검증 결과를 기록한 초안이다. 본인이 직접 수행한 작업·회고는 확인 후 추가한다.

## 구현 과정

1. 6주차의 movie 프로젝트와 공통 응답, PasswordEncoder, 회원·평점 엔티티/테스트를 확인했다.
2. JJWT 0.12.6 의존성과 환경변수 설정을 추가했다. 운영 키는 코드에 넣지 않고 테스트 프로필만 별도 테스트 키를 쓴다.
3. ApiException을 추가하고 기존 전역 예외 처리에 해당 예외의 HTTP 상태·도메인 코드를 보존하는 처리를 추가했다.
4. 이메일 조회 → bcrypt matches → JWT 발급 순서로 로그인 API를 만들었다. 없는 이메일과 틀린 비밀번호는 같은 AUTH401_1과 메시지를 반환한다.
5. AuthInterceptor에서 토큰을 확인하고 요청 속성에 검증된 회원 ID를 저장했다. 공개 경로는 메서드와 함께 구분했다.
6. 내 정보 조회·수정 DTO를 만들고 비밀번호가 응답되지 않도록 했다. 본인 닉네임은 허용하고 다른 회원 닉네임은 409로 막았다.
7. 평점 쓰기 경로를 /ratings로 옮겼다. 작성자는 토큰에서 구하고, 수정·삭제 시 평점 작성자와 비교한다.
8. 삭제를 204에서 200으로 변경해 공통 응답과 result:null을 보냈다.
9. 선택 미션으로 @LoginMember와 ArgumentResolver를 추가해 컨트롤러의 요청 속성 직접 접근을 제거했다.
10. 기존 6주차 테스트를 새 경로·토큰·응답에 맞춰 갱신하고 JWT 및 인가 회귀 테스트를 추가했다.

## 트러블 슈팅

### 이슈 1: 기존 평점 테스트 실패

- 이슈: 6주차의 /members/{memberId}/ratings 쓰기 요청을 사용하던 테스트가 새 구현에서 실패했다.
- 문제: 토큰 기반 경로로 변경되어 URL·인증·등록 응답·삭제 상태 코드가 모두 바뀌었는데 테스트는 기존 계약을 검사했다.
- 해결: 보호 요청에 토큰을 넣고 /ratings 경로를 사용하게 변경했다. 등록 result.ratingId와 삭제 200·result:null을 검사하도록 갱신했다.

### 이슈 2: 제거된 옛 경로의 상태 코드 예상 불일치

- 이슈: 옛 POST /members/1/ratings 요청에서 테스트는 401을 예상했지만 실제로 405가 반환됐다.
- 문제: Spring이 허용되는 컨트롤러 메서드를 선택하는 단계에서 요청을 거절하므로 인터셉터에 도달하기 전에 405가 발생했다.
- 해결: 옛 쓰기 API가 제거되어 실제로 쓰기가 수행되지 않는지와 DB 평점 수가 0인지를 확인하고 테스트 기대값을 405로 수정했다.
- 참고: https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-config/interceptors.html

### 이슈 3: 만료 실습에서 60초 뒤에도 통과할 수 있음

- 문제: 유효기간 60초와 별도로 clockSkewSeconds(60) 여유 시간이 있다.
- 해결: 선택 미션의 실제 대기 검증은 같은 토큰으로 약 121초 이후 호출하거나 skew 설정을 조정해야 한다. 이번에는 만료 후 120초가 지난 서명 토큰으로 JUnit 검증했다.

## 학습 후기 초안

인증을 통과한 사용자도 특정 데이터에 대한 권한은 없을 수 있다는 차이를 응답 코드와 DB 소유권 검사를 통해 정리할 수 있었다. memberId를 URL에서 제거하고 토큰 검증 결과만 사용하면 다른 사람의 회원 ID를 보내는 방식의 사칭을 막을 수 있다. JWT의 payload를 읽는 것과 서명을 검증하는 것은 다르며 서버는 반드시 서명과 만료를 함께 확인해야 한다.
