실제 회원 API는 Spring Boot + 임시 H2 DB(MySQL 모드)를 사용했다. 실제 브라우저에서 5173 → 8080으로 요청해 토큰 저장, 인증 헤더 전송, 닉네임 수정, 즐겨찾기 등록/해제, 평점 등록/수정/삭제와 새로고침 후 결과를 확인했다. 회원가입 회귀 테스트도 포함했다.

모의 테스트는 진행 지연, 로그인 실패, 401 만료, 즐겨찾기 저장 실패, 계정 교체/다른 탭 로그아웃, 입력 경계값을 재현했다. 비로그인 직접 접근 제한, 로그인 후 /login 이동 제한, 재시도/중복 제출 방지, 모바일 수평 넘침과 런타임 오류도 확인했다.

백엔드는 기존 JWT/회원가입/평점 테스트와 새 즐겨찾기 테스트를 함께 실행했다. 실제 DB UNIQUE/FK, 회원별 즐겨찾기 분리, 다른 회원 삭제 차단, 양의 정수 입력을 검증했다.

## 캐시 비교 결과

- 닉네임 PATCH 성공 상태를 확인할 때까지 추가 GET /members/me: 0회
- 활성 즐겨찾기 목록에서 DELETE 후 추가 GET /favorites: 1회
- 실제 API 통합에서도 닉네임 수정 직후 추가 GET 0회를 확인
- 실제 삭제 이후 서버의 즐겨찾기·평점 목록이 빈 배열임을 확인

통신 JSON의 calls에는 이후 페이지 직접 이동/새로고침에 따른 GET도 포함된다. `profileUpdateAdditionalGET`은 수정 화면에서 저장 완료까지의 구간만 측정한 값이다. 새 문서로 직접 이동하면 QueryClient도 새로 만들어질 수 있으므로 이 요청들을 수정 직후 재조회와 구분한다.

## 검증 범위의 한계

- 운영 MySQL 연결·기존 스키마·정렬 규칙은 이번 작업에서 검증하지 않았다. 제공 SQL은 실제 MySQL에서 별도 실행해야 한다.
- TMDB는 테스트용 고정 응답을 사용했다. 실사용 영화 조회는 실제 TMDB 토큰 설정 후 확인해야 한다.
- 브라우저 엔진은 Chromium, 모바일은 뷰포트 에뮬레이션이다. 실물 기기 및 Firefox/Safari를 검증한 결과는 아니다.
- 실패/진행 상태 이미지 중 mocked 파일은 모의 응답 결과이며 live-h2 파일은 실제 회원 API 응답이다.
